# Импорт схем из отчётов ИИ


Для работы без создания файла используйте [текстовый код схемы](CIRCUIT_CODE.md). Кнопка «Код и импорт» копирует промпт для этого языка. JSON ниже остаётся совместимым форматом.

Logic Studio принимает файл `.json`, вставленный JSON или Markdown с **одним** блоком `json`. В отчёте может быть текст вне блока; описание внутри `description` сохраняется и показывается в свойствах проекта. Текст отчёта не исполняется.

## Готовый промпт

> Создай схему для Logic Studio, решающую следующую задачу: [ЗАДАЧА]. Верни краткое объяснение и один JSON-блок по формату ниже. Укажи title и description, полные списки components, wires и texts. Каждый id уникален, содержит латинские буквы, цифры, _ или -. Провода соединяют выход с входом по точным pid из таблицы. Все бинарные источники имеют state.on: true / false; числовые источники имеют state.value. Размести блоки слева направо: шаг 220 px между колонками, 160 px между строками, оставь место для пинов. Координаты x 80–3000, y 80–2000. Проверь типы, разрядность, все ID и соединения. Используй только реально поддерживаемые компоненты и пины. Не включай inputs, outputs и prevInputs: это вычисляемые значения. Не выдавай схему за проверенную симулятором, если не выполнял проверку.

## Пример

```json
{
  "version": "logic-studio-v2",
  "title": "Инвертор",
  "description": "Y = NOT A. Двойной клик по входу меняет значение.",
  "components": [
    {"id":"a","type":"variable","x":100,"y":160,"state":{"label":"A","on":true},"props":{"bitWidth":1}},
    {"id":"n","type":"not","x":350,"y":160,"state":{},"props":{"bitWidth":1}},
    {"id":"y","type":"indicator","x":600,"y":160,"state":{},"props":{"bitWidth":1}}
  ],
  "wires": [
    {"id":"w1","from":{"cid":"a","pid":"out"},"to":{"cid":"n","pid":"a"},"color":"#5080d9"},
    {"id":"w2","from":{"cid":"n","pid":"y"},"to":{"cid":"y","pid":"in"},"color":"#119e8a"}
  ],
  "texts": [{"id":"t1","x":100,"y":90,"text":"Y = NOT A","size":18}]
}
```

Допускается обёртка `{ "title": "Отчёт", "description": "…", "circuit": { "components": [...], "wires": [...], "texts": [...] } }`.

Ошибки типов, ID, разрядности, рекурсивных библиотек, ссылок и пинов отклоняют весь импорт. Текущий проект остаётся на месте. Цвет берётся от источника: его ответвления автоматически получают одинаковый цвет. История позволяет отменить успешный импорт.

## Пины

Все идентификаторы пинов регистрозависимы. `i` ниже — номер разряда от 0 до `bitWidth − 1`. Разряд 0 младший. В пинах необходимо подставлять число: `a0`, `a1`, а не буквальное `ai`.

| Тип | Входы | Выходы |
|---|---|---|
| `and`, `or`, `xor`, `nand`, `nor`, `xnor` | 1 бит: `a`, `b`; несколько: `a0…`, `b0…` | 1 бит: `y`; несколько: `y0…` |
| `not`, `buffer`, `tristate` | `a` / `a0…`; у `tristate` ещё `en` | `y` / `y0…` |
| `switch`, `const0`, `const1` | — | `out` / `out0…` |
| `clock` | `en` (без подключения генерация разрешена) | `out` / `out0…` |
| `variable` | `in` / `in0…` (можно оставить ручным источником) | `out` / `out0…` |
| `indicator` | `in` / `in0…` | — |
| `input` | — | всегда `out0…`, даже при ширине 1 |
| `probe` | всегда `in0…` | — |
| `splitter` | `in0…` | `out0…` |
| `half_adder` | `a`, `b` / `a0…`, `b0…` | `s` / `s0…`, `c` |
| `full_adder` | `a`, `b` / `a0…`, `b0…`, `cin` | `s` / `s0…`, `cout` |
| `dff` | `d` / `d0…`, `clk` | `q`, `nq` / `q0…`, `nq0…` |
| `rs_latch` | `s`, `r` / `s0…`, `r0…` | `q`, `nq` / `q0…`, `nq0…` |
| `jk_ff` | `j`, `k` / `j0…`, `k0…`, `clk` | `q`, `nq` / `q0…`, `nq0…` |
| `tff` | `t` / `t0…`, `clk` | `q`, `nq` / `q0…`, `nq0…` |
| `register` (legacy) | `d0…` | `q0…` — без хранения |
| `sync_register` | `d0…`, `en`, `clk`, `reset` | `q0…` |
| `counter` | `en`, `clk`, `reset` | `q0…`, `carry` |
| `shift_register` | `d`, `en`, `clk`, `reset` | `q0…` |
| `adder` | `a0…`, `b0…`, `cin` | `y0…`, `cout` |
| `subtractor` | `a0…`, `b0…` | `y0…`, `borrow` |
| `multiplier` | `a0…`, `b0…` | `y0…` |
| `divider` | `a0…`, `b0…` | `y0…`, `r0…` |
| `comparator` | `a0…`, `b0…` | `lt`, `eq`, `gt` |
| `shifter` | `a0…`, `b0…` шириной `ceil(log2(bitWidth+1))` | `y0…` |
| `ram` | `a0…` шириной addressBits, `d0…`, `we`, `clk` | `q0…` |
| `rom` | `a0…` шириной addressBits | `q0…` |
| `display`, `seven_segment` | `d0…` | — |

`props.bitWidth`: 1–16. По умолчанию 1 для базовой логики и триггеров; 4 для числового входа, пробника, арифметики, новых регистров, памяти и дисплеев. `props.orientation`: `east`, `south`, `west`, `north`; по умолчанию `east`. Ориентация не меняет pid.

Преобразователи:

- `decoder`: `props.addressBits` по умолчанию 3. Входы адреса: `a`, `b`, `c`, `a3`, `a4`; выходы `y0…y(2^addressBits−1)`.
- `encoder`: входы `i0…i(2^addressBits−1)`; выходы адреса `a`, `b`, `c`, `a3`, `a4`. Ожидается не более одного активного входа.
- `multiplexer`: `addressBits` по умолчанию 2. Селектор `s0…`. При ширине 1 данные `d0…d(2^addressBits−1)`, выход `y`. При ширине больше 1 данные `dГРУППА_БИТ`, например `d3_2`; выходы `y0…`.
- `demultiplexer`: селектор `s0…`. Данные `d` / `d0…`; выходы `yГРУППА` при ширине 1 или `yГРУППА_БИТ` при ширине больше 1.
- Число отображаемых пинов на сторону ограничено 96. Не генерируйте mux / demux с таким сочетанием ширины и числа групп, что нужный пин выходит за этот предел.

## Состояние

- `switch` / ручная `variable`: `on` boolean; `variable.label` — имя.
- `input`: `value`, целое от 0 до `2^bitWidth−1`.
- `shifter`: `direction`: `left` или `right`.
- `display`: `mode`: `dec`, `hex`, `bin`; `seven_segment`: `dec`, `hex`.
- RAM / ROM: `memory` — массив слов DEC; `null` означает X. `addressBits` 1–5, по умолчанию 4, до 32 слов.
- Тактовые элементы срабатывают по положительному фронту. У новых регистров / счётчика EN и RST необходимо явно подключить. DFF / JK / TFF могут сохранять `q` / `value` и `lastClkHigh`; при генерации нового проекта достаточно начального нуля.

Не используйте старый `register` для памяти. Используйте `sync_register`.

Провод может иметь `bends: [{"x": 300, "y": 200}, …]` (до 16 точек).

## Подсхемы

Создавать определения удобнее в редакторе: выделение → «Подсхема из выделения». Проект экспортируется вместе с `customDefs`. Каждое определение имеет `type: "custom_…"`, `name`, списки `inputs` / `outputs` с `id` и `label`, и `source`:

```json
{
  "components": [{"id":"d","type":"dff","x":100,"y":100,"state":{"q":"0"}}],
  "wires": [],
  "inputs": [{"cid":"d","pid":"d"},{"cid":"d","pid":"clk"}],
  "outputs": [{"cid":"d","pid":"q"}]
}
```

Списки source-портов соответствуют внешним пинам по индексу. Определения могут ссылаться на другие определения проекта; циклы запрещены. Каждый экземпляр содержит независимые `state.childStates`. Старые определения с полной таблицей `table` также принимаются.

## Разрезы проводов

`contact`: вход `in`, выход `out`. Передаёт 0 / 1 / X / Z без памяти. Ножницы вставляют два независимых контакта; без соединения между ними сигнал не проходит.
